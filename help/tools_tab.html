Tools - Image Processing

If you go to the Tools Tab, Image Processing.

I included to facilitate making the canny images and other edge images. Plus do post processing on generated images if desired.

If you drop down the accordion 'image processing load save', you'll see files that are in the 'imgp_files' directory in the root of the program folder. This whole tab works only on image files located here in this directory. Isolated from all other images.

All of the images you load in, or save to, works out of that one folder. That way you don't pollute your whole ecosystem with these pieces of files (images) you're just using to generate an image from. Like a canny image. But you load your image and it goes into the input image box. From there you can process the image in a post process stage.

At each stage. You've got different things you can adjust. Brightness, contrast. You can just run the different stages. Grab the image output at each stage. Send to a ControlNet Input. 'Copy' to the Clipboard to Input into anonther Image Input in LCM-LoRA Studio, or 'paste' into a another application.

It'll also do a Depth Map, Edge Detection and Canny.

And once it's done, you can send these directly to your ControlNet input with a button push and/or save the images.

We can send a grayscale if you do a depth map on it. It'll do a depth map on the adjusted image and the output will end up in the grayscale. Stage two. Once it's done, you click the button and it'll send it directly to ControlNet 1.

Speaking of ControlNet stuff, I made a simple, real simple Openpose editor. You can check it out. It's got its own instructions. It opens up in a separate tab in your browser and it's just a web page with JavaScript in it.



Tools - Manage Images

This part of the program is what you can use to delete images from your output folder. When you go to that tab, it's all of your outputs.

If you click on one of the images, it'll display the prompt.

And that's it. You can click on them. So you can browse through it and look at your outputs. It's another way of looking at your outputs, like the output gallery, except through this way. Once you've got one on the screen, you can drop the accordion down at the bottom of the page, where it says 'image text parameter to (delete hidden for safety)' and delete it.

It deletes the picture AND the text parameter file that goes with it.

You've got to close the picture for it to refresh that whole list, which is why I mentioned somewhere else in this documentation. You might want to keep the number of images in your output folder down because it slows this part of the program down. It's a Gradio Cache thing :)

But once you hit delete, as soon as you close that picture, the whole thing will get refreshed.

Now if you don't close the image, eventually a new one will appear. How long depends on how many images are in your output folder.

And that's how you can tame your unwanted output images.



Tools - Manage Models

Under the Manage Models tab, you have the 'LCM-LoRA Models', 'Huggingface', 'Local Cached Models', 'Lora Models', And 'Safetensors Models' tabs. These tabs provide an easy, 'built-in' way, for you to delete unwanted models.

For your 'saved' LCM-LoRA Models, LoRa Models, and Safetensors Models, that you have the 'base' Model itself, plus a possible, Model's 'Gallery' of images, and a 'Model Card', it's a separate delete for the Gallery and Model Card.

You have to check the boxes at the bottom to delete amything, it won't delete it and it'll tell you that.
The checkboxes serve as a type of "Confirm to Delete?' dialog.

For Huggingface it just deletes the folder the model is stored in. Which will make it go download it again because it can't find it. If you think you got a corrupt one, I guess you can delete it and just go tell it to get it again, or just try and use it. It will go get it, if you just simply try and use it. That's one of the reasons I put that in there. Otherwise, I normally don't touch the Huggingface models. Once downloaded, I leave them be. But sometimes files do get corrupt.
Of course this only applies if models appear in the Huggingface dropdown box. If they do not, that can be fixed in 'Settings', see the 'Huggingface Hub Cache' location setting.
